# my-rails-template

## What this is

A Rails application template (`rails new myapp -m template.rb`), not an app itself — running it against a fresh Rails 8.1+ app generates a full starter: auth, admin panel, background jobs, CSS, i18n, deployment config. `template.rb` is a thin orchestrator that `apply`s each file under `template/` in order, inside Rails' `after_bundle` hook. Used by one person (the repo owner) to bootstrap new personal Rails apps.

## Domain

The nouns here are template modules, not app models — see `TEMPLATE_STRUCTURE.md` for the full list and `template.rb` for apply order (order matters: `models` and `routes` must run before `appkit`). Each `template/*.rb` file uses Rails' generator DSL (`generate`, `route`, `gsub_file`, `create_file`, `inject_into_file`, heredocs of generated source) to write files into the target app, not to run any logic itself.

What it generates: session-based auth, first-run bootstrap, session transfer/QR handoff, PWA/push, and theme/preferences come from the external `appkit` engine (github.com/eirvandelden/appkit) — `template/appkit.rb` only wires it into the host app (mount, initializer, `Appkit::Authenticatable`/`Appkit::SessionBehavior` on `User`/`Session`, CSS imports). Role-based authorization (`user`/`admin` enum, `Authorization` concern) stays app-side. CSS comes from the classless `mvpa-css` gem (github.com/eirvandelden/mvpa.css). Background jobs run on Solid Queue; Mission Control monitors them.

`UPGRADING.md` documents versioned migration chapters (identified by commit SHA) for apps generated by older template versions — read it before touching any already-applied module, since changing a module's generated output silently breaks that upgrade chapter's instructions.

## Commands

No Gemfile/Rakefile at the repo root — this repo isn't bundled or run, only its generated output is. Tests are plain Minitest scripts asserting on the *template's* string output (e.g. that `template.rb` applies modules in the right order, that generated ERB matches expected YAML):

```bash
ruby test/database_setup_test.rb
ruby test/testing_template_test.rb
ruby test/appkit_template_test.rb
```

`.rubocop.yml` and `lefthook.yml` are symlinks to the shared dotfiles config, same as every other personal repo.

## Gotchas

- `test/appkit_template_test.rb#test_deleted_template_files_are_gone` currently fails: it expects `template/theme_system.rb` deleted (superseded by the `appkit` engine) but the file is still present. Pre-existing, not caused by this change — don't "fix" it by deleting the file without checking whether `theme_system.rb` is still referenced elsewhere first.
- Editing a `template/*.rb` file changes what new apps generate, not this repo's own behavior — there's nothing to `bin/rails` here.
- `template/appkit.rb` only wires the engine in; auth/theme/PWA logic itself lives in the `appkit` gem and is fixed there, not here.
